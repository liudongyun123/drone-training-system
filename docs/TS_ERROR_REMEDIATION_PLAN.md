# TypeScript 历史错误分批整改计划

> 生成日期：2026-07-14
> 当前错误数：**256**（基线 272，已通过 `scripts/type-check-gate.mjs` 门禁，门禁只阻断**新增**错误，且每修复一个会自动收紧基线）
> 构建状态：`npm run build`（esbuild）**不受影响**，256 错误均为类型层问题，不阻断运行。

## 一、错误分类（按 TS 错误码）

| 错误码 | 含义 | 数量 | 风险 | 修复难度 |
|---|---|---|---|---|
| TS6133 | 声明了但未使用（import/变量） | ~153 | 低（纯噪音） | 极低（可自动化） |
| TS2339 | 访问不存在的属性 | ~87 | 中（运行时可能 undefined） | 中（需补类型/断言） |
| TS18046/18047/18048 | 严格空值检查："可能为 undefined" | ~48 | 中 | 中（加 `?.`/`??`） |
| TS2345 | 函数参数类型不匹配 | ~23 | 中 | 中 |
| TS2571 | 对象类型为 unknown | ~10 | 低 | 低（补类型） |
| TS2322 | 类型不可赋值 | ~10 | 中 | 中 |
| 其他（TS4114/2769/2304/7030/7053/7006/2552/2551/2538/2353/2305/2774/2614/2367/2352） | 杂项 | ~15 | 低~中 | 低~中 |

> 注：以上为 `npx tsc --noEmit` 原始分类，合计与门禁 256 存在统计口径差异（门禁可能合并同文件），比例分布仅供参考。

## 二、风险分级

- **P-低（噪音型）**：TS6133、TS2571、TS7030、TS7006、TS2304、TS2551 等——不影响运行，主要拖慢编译、污染编辑器。
- **P-中（潜在运行时隐患）**：TS2339、TS2345、TS18046/18047/18048、TS2322、TS2367——字段名/类型与运行时数据结构不符，可能在特定数据下取到 `undefined` 导致白屏或逻辑错误（如本项目中已修复的 `AdminFinance.paidUsers`、`AdminTransfers.data`、`CourseForm.realName` 等）。

## 三、分批整改计划

### 阶段 1：清理未使用代码（TS6133 为主，约 153 个）
- **范围**：所有 `is declared but its value is never read` 的 import 与局部变量。
- **方法**：
  1. 运行 `npx eslint src --fix`（ESLint `no-unused-vars` 可自动删除大部分未使用 import/变量）。
  2. 对 eslint 无法安全删除的（如被类型引用但未值引用），手动加 `// eslint-disable-next-line`。
- **验收**：TS6133 归零；`type-check-gate` 基线自动下降约 153，门禁仍绿。
- **预计**：1 次自动化 + 少量人工，约 0.5 天。

### 阶段 2：补强关键业务类型（P-中，约 120 个）
- **范围**：TS2339 / TS2345 / TS2322 / TS2367。
- **方法**：
  1. 优先处理**后台管理核心模块**（`src/admin/**`、`src/services/**`）：这些页面有真实用户操作，错误最可能导致线上问题。
  2. 对云函数返回的数据结构，在 `src/types/` 与 `src/services/**` 中补齐接口字段（如 `RevenueStats.paidUsers?`、`TransferBatchResult.data?`、`Teacher.realName?`）。
  3. 对确实动态的结构使用 `as any` 或可选链 `?.`，并加注释说明原因。
- **验收**：后台模块零 TS 错误；e2e 全绿不变。
- **预计**：2~3 天，按模块拆分 PR。

### 阶段 3：严格空值检查（TS18046/18047/18048，约 48 个）
- **范围**：`possibly undefined` 类错误，集中在 `src/web/**`（前端 H5）与部分 admin 列表页。
- **方法**：加可选链 `?.` 与空值合并 `??`；对列表项先做存在性判断。
- **验收**：相关页面类型干净。
- **预计**：1~1.5 天。

### 阶段 4：杂项与未知类型（约 15 个）
- **范围**：TS2571(unknown)、TS4114、TS2769、TS7053、TS2305 等。
- **方法**：逐个补类型或收窄类型；对第三方库类型缺失使用模块声明 `declare module`。
- **验收**：全仓 `tsc --noEmit` 零错误（或仅剩明确标注 `@ts-nocheck` 的文件）。
- **预计**：0.5~1 天。

## 四、执行原则

1. **绝不一次性全量开启 `strict`**：当前 `tsconfig` 非全 strict，直接开 strict 会瞬间爆量。保持现状，逐文件收紧。
2. **分批小步提交**：每阶段一个小 PR，门禁自动收紧基线，保证主干始终可构建、可部署。
3. **优先业务核心**：阶段 2 先做后台（有真实管理员操作），再做 `src/web` 前端 H5。
4. **不删业务代码**：TS6133 删除前确认非被反射/动态引用（如组件名作为字符串 key）。
5. **e2e 守护**：每阶段修复后跑 `npx playwright test`，确保 225 用例持续全绿。
